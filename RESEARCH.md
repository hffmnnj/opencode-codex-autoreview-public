## Stricter parent rule in this plugin

This plugin requires a completed same-session parent with matching model, account, and authorization before sending a review, and it never invents a parent response ID. That is a deliberately stricter safety/attribution rule, not an established universal backend requirement. Codex retains the last observed `response.created` ID, including a started response that later failed, until a newer ID arrives, and its tests also admit review requests without any parent ID. See [`codex-rs/core/src/client.rs#L1190-L1243`](https://github.com/openai/codex/blob/8c076942cb70fba8e5c4732c23f1faabc4aed484/codex-rs/core/src/client.rs#L1190-L1243) and [`codex-rs/core/tests/suite/guardian_review.rs#L270-L299`](https://github.com/openai/codex/blob/8c076942cb70fba8e5c4732c23f1faabc4aed484/codex-rs/core/tests/suite/guardian_review.rs#L270-L299). These fixture tests do not prove live acceptance without a parent.

## Why the prototype is advisory/deny-only

- Default `shadow` mode leaves the permission and UI message unchanged; explicit opt-in `enforce` mode may change only the current ask to deny. Allow verdicts always remain manual (`approval-unproven`). Existing allows and explicit denies are never reviewed or changed. No mode creates an `always` approval or writes saved permission rules.
- The OpenCode 2.0.25 permission event exposes an action, resource labels, optional metadata, and call identity, not the final executor arguments or all effects; see [`permission.hook("evaluate")`](https://opencode.ai/v2/docs/build/plugins). Input identity therefore does not certify every effect of arbitrary registered tools, and native model user roles do not prove human authorship of the context. A generic final executed-action certificate and attributable human authorization are not established, so safe automatic approval is blocked pending a separately designed final-action/provenance contract or narrowly certified tool adapter.
- This plugin expressly claims no Codex sandbox, filesystem boundary, network restriction, or rollback. The upstream context sources above were used for evidence/provenance shape only; a no-tools first version loses Codex's confined read-only investigative capability and must defer to manual approval when local-state evidence is needed.
